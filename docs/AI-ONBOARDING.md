# ورود AI جدید به پروژه (onboarding)

وقتی می‌خواهی AI دوم (دستیار دیگری در هر چت‌بوکسی) وارد همکاری شود، فقط دو قدم:

## قدم ۱ — توکن جدا برای AI جدید
همین مراحل کلید قبلی، با همین مشخصات:
- **fine-grained** | فقط repo `saya_jadu` | **Contents = Read and write** | 30 روز
- (Pages دیگر لازم نیست — سایت فعال است)

## قدم ۲ — این متن را کپی کن و در چت AI جدید paste کن

```
حالا می‌خواهم روی پروژه «سایا-جادو» با من همفکری و همکاری کنی.

ریپوی پروژه (private): https://github.com/alimoee/saya_jadu
توکن تو (فقط این repo، Contents): <TOKEN_AI_2>

با REST API (api.github.com/repos/alimoee/saya_jadu/contents/<مسیر>)
فایل‌ها را بخوان — به‌ترتیب، قبل از هر کاری:

1. PROTOCOL.md        ← قوانین همکاری (issue = برد وظایف، commit/PR = هاندآف،
                          برچسب claim «در-ادامه-<نام-AI>»، مالک = تصمیم‌گیر نهایی)
2. docs/SAYA-Prompt-v1.2.md   ← سرلوحه پروژه (اصل هدایت همه کارها)
3. docs/SAYA-Review-1405.md   ← بازبینی بازار 1405 (فکت‌ها و منابع)
4. docs/AI-ONBOARDING.md      ← همین فایل

بعد از خواندن:
- open issueها را بخوان؛ اگر نبود، index.html (صفحه دمو) را بررسی کن
  و اولین پیشنهادت را به‌صورت issue با عنوان واضح بنویس.
- هر وظیفه = یک issue جدا → claim با برچسب «در-ادامه-<نامت>» →
  انجام → commit با message فارسی واضح.
- قوانین سخت PROTOCOL: هیچ secret/کلید در repo، هیچ داده ساختگی بدون
  علامت «دمو»، conflict → issue بزن و برچسب «تصمیم-مالک» بگذار.
- شروع کن با: خلاصه ۳ خطی از وضعیت فعلی پروژه + اولین issue پیشنهادی.
```

## برای خودت (مالک)
- AI جدید را با نام مشخص صدا بزن تا برچسب claimش مشخص باشد (مثلاً «AI-B»).
- تو همیشه merge/تصمیم نهایی را داری — حتی اگر AIها نظرشان یکی باشد.
- هر AI یک توکن خودش را دارد؛ اگر یکی بی‌کار شد، همان را از
  `settings/personal/access-tokens` لغو کن، دیگری دست‌نخورده می‌ماند.
