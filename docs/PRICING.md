# سایا-جادو — قیمت‌بندی، تریال، باتری و ریکاوری (v2.2 — ۱۴۰/۶/۲)

دستور مالک: ۱۰ روز تبلیغ رایگان با بررسی اطلاعات، بسته‌بندی قیمت با حاشیه‌ی
سود ۳۰٪ روی مخارج واقعی (سرور و بقیه)، باتری نمادی مثل موبایل، اخطار قرمز و
یخ‌زدگی بعد از موعد، و هزینه‌ی ریکاوری به ازای هر روز. همه‌ی اعداد این سند در
`bot/pricing.py` و `docs/unit-econ/unit_econ.py` (selftest با assert حاشیه) هستند.

## ۱) تریال ۱۰ روزه (تبلیغ)

مسیر مشتری در ربات (تلگرام):

```
/start (یا هر پیام اول)
  → ۷ سؤال کوتاه: نام / نام مغازه / صنف / شهر / موبایل / چند مشتری / چند قلم
  → «🔍 در حال بررسیِ اطلاعاتت…» (بررسیِ صادقانه و خودکار)
  → «✅ X٪ اطلاعات واردشده بررسی و صحیح است» (جزئیات هر قلم با ✅/⚠️)
  → «🎁 ۱۰ روز آزمایش رایگان — باتری ۱۰۰٪»
  → مالک هم‌زمان اعلان «مشتریِ جدید» می‌گیرد (/manage)
```

**چه چیزهایی واقعاً بررسی می‌شود** (صادقانه — ادعای جعلی نمی‌کنیم):
| قلم | بررسی |
|---|---|
| نام و نام مغازه | حداقل ۲ حرف |
| صنف | تطبیق با فهرست ۱۲ صنف (ابزار، عطار، رستوران، …) |
| شهر | تطبیق با فهرست ۴۹ شهر بزرگ |
| موبایل | فرمت 09 + ۱۰ رقم (شماره‌ی نامعتبر تا ۲ بار برگشت می‌خورد) |
| مشتری/قلم | عدد معتبر ۱ تا ۹۹٬۹۹ |

درصد = تعدادِ ردشده / ۶ × ۱۰۰. اگر هرچه بخواهد **بلوکه نمی‌شود** (دستور مالک:
«ادامه بده») — فقط درصد پایین می‌ماند و مالک می‌بیند.

**اعتبار تریال** = شاملاتِ بسته‌ی «شروع» (۳۰ گفتگو + ۳ فاکتور + ۰ دقیقه صدا
= ۳۲۴ واحد) برای ۱۰ روز. هزینه‌ی واقعی هر تریال ≈ ۱۷٬۹۰۰ تومان (unit-econ v2.2).

## ۳) نرخ‌های اضافه (فراتر از شمول)

| مورد | نرخ |
|---|---:|
| هر ۱۰ مشتریِ اضافه | ۷۵٬۰۰۰ تومان/ماه |
| هر ۵۰ قلمِ اضافه | ۵۰٬۰۰۰ تومان/ماه |
| هر ۱۰۰ گفتگوِ اضافه | ۱۰۰٬۰۰۰ تومان/ماه (= ۱٬۰۰۰/گفتگو) |
| هر ۳۰ فاکتورِ اضافه | ۱۵٬۰۰۰ تومان/ماه (= ۵۰۰/فاکتور) |
| هر ساعت تماس و جواب‌گوییِ اضافه | ۹٬۰۰۰ تومان (= ۱۵۰/دقیقه) |

نرخ‌های گفتگو (۱٬۰۰۰) و فاکتور (۵۰۰) همان تأییدِ ۲۵ شهریورِ مالک هستند و
«باتری» دقیقاً با همین نرخ‌ها می‌سوزد — یعنی قیمتِ اضافه = نرخ باتری، بدون
پنهان‌کاری.

## ۴) باتری نمادی (مثل موبایل)

- **۱ واحد** ≈ ۱٬۰۰۰ تومان خدمت: گفتگوی متنی = ۱ · فاکتور = ۰.۵ · هر دقیقه صدا = ۰.۱۵
- نمایش: «🔋 ۷۸٪» — مشتری می‌داند چقدر اعتبار دارد (`/battery`)
- **< ۲۰٪**: هشدار «باتری کم است، زودتر شارژ کن»
- **صفر**: «🔋 باتری خالی شد — رسید بفرست یا با صاحب مغازه تماس بگیر»
- هر استفاده از حساب می‌کُشد؛ هر شارژ (+۳۰ روز) باتری را پر می‌کند

## ۵) پس از موعد: اخطار ← یخ ← ریکاوری

| روزِ عقب‌ماندگی | رفتار ربات |
|---|---|
| ۱ تا ۷ | باتری **چشمک‌زن** (🔴/⚫) + «⚠️ اطلاعاتِ شما حذف خواهد شد — رسید بفرست» (روزی یک‌بار) + اعلان به مالک |
| ۸ به بعد | **یخ‌زدگی** ❄️ — منشی جواب نمی‌دهد؛ **داده‌ها در سرور می‌مانند** (حذف نمی‌شوند) |
| هر روزِ یخ | **حق‌البازگشت: ۳٬۰۰۰ تومان/روز** (از روز هشتم) |

**مسیرِ بازگشت:**
1. مشتری **عکسِ رسید** را همان ربات می‌فرستد → ربات رسید را برای مالک می‌فرستد
2. مالک (با دسترسی‌ای که خودش تعیین می‌کند — فعلاً چشمِ خودش روی حساب) تأیید می‌کند:
   `/charge <نام>` → حساب فعال + ۳۰ روز + باتری پر
   یا `/recover <نام>` → ابتدا حق‌البازگشت محاسبه می‌شود، مالک با `yes` اعمال می‌کند
3. **مدیریتِ دستی مالک** (مالی و رفتاری): `/manage` (فهرست) · `/freeze` · `/thaw` ·
   `/note` (یادداشت رفتاری) · `/plan <نام> <بسته>` (ارتقا/تنزل)

> «اطلاعاتِ شما حذف خواهد شد» متنِ اخطارِ انتخاب‌شده است؛ **داده واقعاً
> حذف نمی‌شود** (دستور مالک: داده بماند تا با هزینه‌ی ریکاوری برگردد).

## ۶) عددِ ریکاوری از کجا آمد

هزینه‌ی نگهداری داده ≈ ناچیز (در سرور) — ۳٬۰۰۰/روز (= ۹۰٬۰۰۰/ماه) یک **نرخ بازدارنده**
است، نه هزینه؛ هدفش این است که مغازه‌دار یا شارژ کند یا آگاهانه تصمیم بگیرد.
مالک هر زمان می‌تواند با `/charge` عفو کند (بدون ریکاوری) — اختیار دست اوست.
